# Bus

Event bus: publishes domain events to the registered subscribers in the publisher's transaction: kudosGiven to the welcome message, progression, Quests' Journey and weekly quests, the leaderboard's totals, and the analytics module's recording of kudos given and kudos received; attemptFailed and memberWelcomed to the analytics module's recording of attempt failed and member welcomed; levelReached, which progression publishes, to Unlocks, which records the level up and its readiness and sends the level-up DM in one mutation, and to feedback's public level notice; xpRecorded, which progression publishes from the transaction that records a member's XP, to feedback's App Home refresh; unlockReady, which Unlocks publishes and nothing subscribes to yet; unlockOpened, which Unlocks publishes, to Quests' weekly draw, scheduled only for the Quests feature, and to the Journey's activation, scheduled only for a feature that opens a Journey step and never for an opening by Unlocks' launch, since a subscriber may name which events it takes so that Unlocks' launch, which opens every shipped feature for every member already playing in one mutation, schedules nothing for the others; questFinished, which Quests publishes, to the Journey's `first-quest`, scheduled only for a weekly quest, and questOpened, which Quests publishes and nothing subscribes to yet; perkBought, which progression publishes from the mutation that buys a perk and nothing subscribes to yet; and memberLeft and memberRejoined, which the directory publishes when a member stops being one and when one comes back, to the Journey's `someone-new`. levelReached carries the kudos message only when an award reached the level; a level reached through a reward record has none, so its public level notice goes only to the announcement channel, keyed by the member and the level, and nowhere while none is picked. Commands are not domain events: the command registry in convex/commands routes them.
