opaque analytics ID per member and a workspace key per workspace. It keeps PostHog's person for each analytics ID on the member's profile: their email, real name, display name, title, Slack user and team ID, whether they are an admin, the handles of their user groups and the environment, sent only as the person properties of an $identify after the analytics ID is created and of a $set after the directory or a user group changes them, unsetting what the profile lost, each recorded by a job those mutations schedule (one shared job for every analytics ID still waiting for its first), which reads within a budget and hands the rest to the next job, with a one-way fingerprint of the last profile recorded so a repeated one records nothing; only a person event carrying its analytics ID's current fingerprint is ever sent or retried, one a drain sent after losing its claim has its analytics ID's current profile recorded again, one whose delivery failed, or that a drain held when its lease expired, leaves its analytics ID uncertain until the next daily pass sends the current profile again, a given-up person event forgets its fingerprint, and a daily pass after the user group sync, the profile backfill and a user group rename record whatever is missing. One drain at a time sends due events to PostHog's batch endpoint, at most 100 per request, deleting them when PostHog answers 2xx. A batch PostHog doesn't accept is retried with the same identity after successive delays of 1, 5, 30, 120 and 360 minutes; a rejected batch, an event that fails a sixth time and one still pending 7 days after it was recorded are exhausted, logged and deleted 7 days later. Claims carry a lease token, and a recovery check at each lease's expiry releases a dead or stalled drain's batch and replaces that drain, whose generation then claims nothing. It is also the feature flag seam: a flag is declared once with its key, values and safe default, and is answered twice through the PostHog component's locally evaluated definitions: the member decision on the member's analytics ID with the person properties environment and, when the directory holds one, email, and the workspace decision on the workspace key with environment only (in a query, a member without an analytics ID gets the workspace decision); it sends its exposure once per member, flag and value, only when the flags key is set, since without it nothing was evaluated. Its error boundary wraps every HTTP route and action outside the module and records an error nobody caught as one exception event before rethrowing it marked [reported]; a route that carries kudos text, the Slack events route, sends even a reportable error as unexpected error, and when it records nothing rethrows the error with a fixed message in place of its own; its failed-job sweep, every 15 minutes, records each scheduled function that failed without a boundary reporting it, rereading the jobs created at its cursor's instant so a job tied with the last one it read is not skipped. A recording mutation that fails logs a fixed code and is never recorded as an exception. Only a reportable error sends its message. With native error reporting switched on, neither records anything. Every function is internal; the PostHog spec is issue #69.
