# Unlocks

Unlocks: owns each member's ready and opened features (P72 to P79, P92, ADR-0006). The schedule is versioned catalogue data with stable feature IDs, each feature shipped by its own flag, so far quests by quests, the leaderboard by everyone-board, the Book by achievements and the skill tree by skill-tree; a feature that hasn't shipped is never ready, named or counted. It subscribes to levelReached and stores readiness, with its time, for every shipped feature at or below the level reached, once, publishing unlockReady and republishing App Home, records each level up once, with the features it made ready and the level up's time, before writing anything else, so a replayed levelReached writes nothing, and reads a member's level ups newest first by that time for the activity; subscribes to a feature's ship through the ship sweep, which every hour, a page of 25 members per mutation so no mutation schedules or reads more than Convex allows, each member deciding every ship flag for themselves, stores readiness, with the sweep's time, for every member at or past the level of a feature shipped for them who has none, publishing unlockReady and republishing App Home, and in the same mutation has feedback send each such member one DM naming exactly the features that sweep made ready; and in the same mutation has feedback send the level-up DM naming exactly the features that mutation made ready, so each ready feature is named in one DM whichever subscriber runs first; the openUnlock command opens a ready, shipped feature for good, storing openedAt and publishing unlockOpened, and refuses anything else without writing; stateOf answers unshipped, locked, ready or open from the stored facts and the ship state, never from the level; and it gives App Home the ready features with what each opens and the next shipped feature still locked, and the website each shipped feature's state, readyAt and openedAt. Opening only reveals: it grants nothing. Unlocks ship dark behind the unlocks flag, off by default, which needs xp-levels. Whether a feature has shipped for a member, the readiness a level up or the ship sweep stores for them, what App Home, a DM or the unlock filter shows them and whether openUnlock opens for them follow that member's decision of each flag it needs (F17, F20), and a viewer the directory doesn't know gets the workspace decision (F19). Every mutation that sees unlocks live in a workspace also launches the Book there where it applies. The first mutation that sees unlocks and xp-levels on in the workspace decision launches unlocks there once: it stores that moment and the features shipped in the workspace decision then, and opens each of those features, at that moment and without a DM, for every member who existed then, whatever their level (P77, F21), marking each such unlockOpened as the launch's, and publishes unlocksLaunched for every opening it stored, 1,000 openings to an event, so the launch schedules one analytics job per 1,000 openings rather than one per opening, and no job's arguments come near Convex's 8,192 elements in an array; an opening a member already has keeps its first openedAt and publishes nothing (F23). The first mutation that shows unlocks to a member while their workspace has no launch is that member's preview moment: stored once per member, it opens for them alone every feature shipped in their decision then, at that moment and without a DM, marked as the launch's, and publishes unlocksLaunched for the openings it stored (F22). Readiness is recorded whatever the unlocks flag says; while it is off for a member, they are shown nothing of unlocks and openUnlock refuses.
