# Feedback

Feedback: the indicator on each kudos message as desired state and the private reply to its giver, both written with the outcome and delivered by the adapter afterwards; notifications as DM intents to one member that honour their DM setting (on unless turned off): one level-up DM per level up Unlocks records, sent from the mutation that makes its features ready and naming each of them with an Open button, and one DM per member from each ship sweep that makes features ready for them, naming each with an Open button the same way; the one public reply per kudos message as desired state, whose sections modules set and whose routing (the announcement channel and muted notices) feedback decides; App Home as desired state, published again for a member after each xpRecorded about them while `xp-levels` is on, so it never shows XP from before the record, after Unlocks makes a feature ready for them, for every admin after the announcement channel changes, and after a role change or a click, and again when what it shows changed while it was sent: one homeSelections row per member holds the tab and leaderboard period they last picked, and its tab bar shows each tab only while its own flag is on, Leaderboard while `everyone-board` is on and, while `xp-levels` is on, only once the member has opened the Leaderboard, Admin with the announcement channel picker for workspace admins and owners while `xp-levels` is on, Settings while either is on, with the leaderboard switch only while `everyone-board` is on and muting notices and DMs only while `xp-levels` is on, and Profile beside any of them, with the member's allowance and kudos given and received and, while `xp-levels` is on, their level, XP to the next level, skill points saved from level 5 once the skill tree is open, each ready feature with what it opens and an Open button, and the next shipped feature still locked; with both flags off App Home has no tab bar and shows only the core loop's allowance, totals and hints, and a remembered tab whose flag is off opens as Profile; and the copy every reply is rendered from: the private replies, the welcome message, the level-up DM (which names saved skill points, for the skill tree, only from level 5 and only once the member has opened the skill tree, and each feature the level up made ready with what it opens, as App Home does), the public level notice, App Home, the `/hedgehug` replies, and the rows of a board with its improvement line, all naming the product HedgeHug. The unlock filter asks Unlocks' stateOf before any line that tells a member about their own progress in a feature, and leaves the line out until that member has opened the feature; Unlocks' own lines, the ready crates and Next, are exempt, and the filter never changes what is earned or stored. A command for a shipped feature the member hasn't opened replies `{Feature} is ready for you. Open it in App Home.` once it is ready, and `{Feature} opens at level {n}.` before; what other members see of them, such as their row on a board or the `Show me on the leaderboards` switch that governs it, follows what has shipped, never their unlocks.

## invariants
- private replies reach only the giver: A private reply about a kudos message reaches only its giver: an ephemeral to the message's author beside the message, in the thread for a thread reply and in the channel otherwise, and nobody else, recipients included, is sent anything about it.
  over: every message the app asks Slack to send for a Given, an Over allowance and an Invalid kudos message, posted in a channel and in a thread
  via: R33: replies reach only the giver
  because: R33 keeps feedback private: the giver alone learns what was spent, who was skipped and why, and a recipient or a channel must never get a message the giver did not write; a reply sent to the wrong person or posted publicly would leak allowance and skipped-mention reasons
  refuted: sendPrivateReply posted the reply with chat.postMessage instead of chat.postEphemeral -> all 6 cases failed on their only-an-ephemeral-to-the-giver assertion, with every welcome DM named (2026-10-13)
  kinds: output, message
  checklist: destination-confinement dismissed: the reply goes to the Slack Web API at one configured base URL, with no redirect followed and no destination taken from input
  checklist: message-authenticity dismissed: the reply is outbound; the inbound message it answers is verified by the Slack adapter's signed Slack requests only
  checklist: redaction dismissed: a reply holds only the app's copy and mentions, never the message's text, so there is nothing designated sensitive to scrub
  checklist: input-validation dismissed: the reply is rendered from the engine's outcome, never from outside input
  checklist: retry-recognition dismissed: retrying a reply is the Slack adapter's delivery, which bounds it by its invariant a private reply is tried at most 3 times; a retry resends the same stored reply to the same giver, so it cannot widen who is told
  checklist: duplicate-suppression dismissed: the reply is written once in the evaluation's transaction, and a redelivered event never re-runs the evaluation (R19)
  checklist: keyed-ordering dismissed: one reply per evaluation, with no ordering promised between messages
  checklist: acknowledgment-barrier dismissed: nothing retires work on the reply's acknowledgment
  checklist: commit-ordered-effects dismissed: the reply row and its delivery are scheduled in the evaluation's transaction, and the delivery runs only after it commits
  checklist: retry-classification dismissed: the Slack adapter's delivery classifies failures, by its invariants a private reply is tried at most 3 times and a gone delivery stops for good
  checklist: circuit-breaker-policy dismissed: no breaker is declared for Slack delivery
  checklist: declared-target-coverage dismissed: a reply has exactly one target, the giver
- one public reply per kudos message: A kudos message gets at most one public reply in each place it is celebrated, its thread or the announcement channel: the reply is posted once and then edited in place as sections arrive, however many members level up through the message and whenever their sections arrive, and a post whose outcome is unknown, or that failed after Slack accepted it, is never posted again.
