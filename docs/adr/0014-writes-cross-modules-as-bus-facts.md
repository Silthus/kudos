# Writes cross modules as bus facts, and reads call seams

A module that changes another module's state publishes a fact on the bus, and the owner follows it. A module that needs another module's state calls that module's seam. So Hugs publishes `hugGiven`, `hugReceived` and `hypeReacted` instead of calling `recordReward`, and Quests publishes `questFinished` instead of calling `recordReward` and `earnItem`. A guard test fails on any import of another module's write function, or any query of another module's table, that is not on its allowlist, and the allowlist may only shrink. The one direct write that stays is the turn, which draws, shows and records milestones in the request the member waits on ([ADR-0010](0010-hidden-items-are-a-ledger-drawn-at-the-turn.md)).

We chose followers over direct calls in one mutation. Direct calls made every new feature reach into `Progression`, Items and `Hoggies`, and seven files had come to call `earnItem`. Each follower runs in its own mutation, so effects land a moment after the fact and are not atomic with it. Convex retries a scheduled mutation only on its own transient errors, never on a throw, so a follower that throws loses its effect while the others keep theirs. Every follower is keyed, so delivering a fact twice has one effect, and every new follower has a test that delivers it twice. The failed-jobs sweep reports a throw, and an operator replays that job with `bus.replay`. Nothing retries on its own, because a bug that throws would throw on every retry.
