# Kudos domain glossary

The shared vocabulary of the Kudos codebase. Use these words in code, tests, UI copy and tickets, and avoid the ones marked as "not". Each feature area has its own section; add a section rather than redefining a term.

Decisions that are hard to reverse live in [`docs/adr/`](docs/adr/).

## Rewards Store

Specified in [Spec the Rewards Store](https://github.com/Silthus/kudos/issues/4) and moved to Hog coins in [Store: priced in Hog coins with built-in game items](https://github.com/Silthus/kudos/issues/91) ([ADR 0002](docs/adr/0002-store-currency-is-hog-coins.md)). Who may shop and the game items live in `convex/lib/items.ts`, the real-rewards rules in `convex/lib/store.ts`, what each item does in `convex/items.ts`; every balance, stock, purchase or redemption change goes through `convex/store.ts`.

| Term | Meaning | Not to be confused with |
|---|---|---|
| **Store** | Where members spend Hog coins: built-in game items that apply instantly, plus, if an admin switches them on (off by default), real rewards with the redemption workflow. Priced only in Hog coins ([ADR 0002](docs/adr/0002-store-currency-is-hog-coins.md)). It comes with the game (no game, no currency), shows in the menu from level 3 with the wallet, and is visible but locked until level 5 (`SHOP_LEVEL`). | — |
| **Real rewards** | The catalog of things an admin hands over (coffee, a hoodie, a half day off), requested for Hog coins and approved, fulfilled or declined by an admin. Behind the admin switch `realRewardsEnabled`, off by default; the old `storeEnabled` switch (received-kudos prices) is never read. | a *game item*, which needs no admin |
| **Purchase** | One game item bought (`itemPurchases`): the price is debited and the item applied in the same transaction. Monthly limits count purchases by the workspace calendar month. | a *redemption* |
| **Reward** | An item in the catalog that members can request by spending their balance. Archived, never deleted. | "prize" or "item" (don't use these) |
| **Balance** | A member's Hog coins available to spend: the *coin balance* (`coinBalance`). Private to the member and admins, whatever the received visibility, because coins come from giving. It can go negative when a revoke takes back coins already spent, which blocks spending. The received-kudos balance of [ADR 0001](docs/adr/0001-store-balance-is-received-kudos.md) was reset, not converted: its fields (`storeSpent`, `storeGranted`) and its requests and adjustments without a `unit` are never counted. | *received*, which is only a stat |
| **Redemption** | One member's request for one reward, with the cost and reward details frozen at request time. | "order" or "purchase" (don't use these) |
| **Hold / debit** | The cost is subtracted from the balance as soon as a redemption is created. | — |
| **Refund** | When a pending or approved redemption is declined or cancelled, the cost goes back to the balance and stock is restored. | *revoke*, which undoes a *kudos* (engine) |
| **Grant / adjustment** | An audited, admin- or system-made change to a Hog coin balance (`members.coinsAdjusted`), with a reason. Possible whenever the game is on, even with real rewards off. | *kudos*: a grant is not recognition and never appears on leaderboards |
| **Decider** | The admin who approves, fulfils or declines a redemption. | *requester*, the member who redeemed |

## Quests

Specified in [Spec the Quest system](https://github.com/Silthus/kudos/issues/5). The catalog, board draw and evaluator live in `convex/lib/quests.ts` (pure); boards, completions and the engine hooks in `convex/quests.ts`. Quests only measure the member's own *giving*, never what they receive, and progress is never stored: it's recomputed from kudos rows.

| Term | Meaning | Not to be confused with |
|---|---|---|
| **Quest** | A weekly goal about the member's own giving, defined in the built-in catalog (`QUESTS`). | "challenge", "mission", "achievement" (don't use these) |
| **Quest week** | Monday 00:00 to Sunday 24:00 in the workspace timezone, the same week as `resolvePeriod("week")`. Identified by its **week key**, the Monday's `YYYY-MM-DD` day key (`weekKeyOfDay`). | a rolling 7-day window |
| **Quest board** | The 3 quests every member of a workspace gets for one quest week. Seeded draw per workspace-week (`pickBoard`) that keeps at most one of last week's quests and, where it can, avoids the board from two weeks before; stored (`questBoards`) the first time a mutation needs it and never changed after. | — |
| **Note** | The words in a kudos message other than mentions, channel links, URLs and emoji (`countNoteWords`, stored as `kudos.noteWords`). Reactions have no note. | the kudos *text*, the readable preview |
| **Qualifying kudos** | A kudos row whose Note has at least 3 words and that is not Reciprocal. Only qualifying kudos move quest progress. | any kudos: every kudos still counts everywhere else |
| **Reciprocal kudos** | A kudos from G to R where R gave G any kudos in the 72 hours before it. The kudos goes through as normal; it just doesn't move quests. | — |
| **Quest completion** | The stored fact (`questCompletions`) that a member met a quest's goal in a given quest week. Removed again if a revoke means the goal is no longer met. | progress, which is always recomputed |
| **Waived** | A quest on the board that this member can't possibly complete this week (e.g. Unsung hero while received counts are hidden). Shown muted; doesn't count toward a Clean sweep. | "failed": unfinished quests just expire, there is no failed state |
| **Clean sweep** | Completing every non-waived quest on a week's board. | — |
| **Quest message** | A collectible bot message (category `quest_complete`) that can only be obtained by completing a quest. Never Store currency or allowance. With the game on, quests also pay XP and Hog coins (see **Quests on the ladder** under Game). | a Store *reward* |

## Compare

Specified in [Spec Compare stats](https://github.com/Silthus/kudos/issues/6). Pure rules (metrics, visibility, distributions) live in `convex/lib/compare.ts`; one query per benchmark in `convex/compare/`. The page is `/compare?vs=…&period=…`.

| Term | Meaning | Not to be confused with |
|---|---|---|
| **Comparison** | The viewer ("You"), one benchmark, one period and a fixed metric set, shown as a scoreboard and a race chart. | a leaderboard *rank* |
| **Benchmark** | What you're compared against: exactly one of **Past you** (your own previous period), **Team** (the participant distribution) or **Teammate** (one other member). Always drawn in the neutral benchmark ink (`--color-benchmark`). | "opponent", "rival" (don't use these) |
| **Period** | A calendar period from `resolvePeriod`: week, month, quarter or year (default month). Compare has no "all time": it has no previous period and rewards tenure. | a rolling window |
| **Previous period** | The previous calendar bucket up to the same day offset as today (`previousToDate`): on a Wednesday, Mon–Wed against last Mon–Wed. The race chart also shows how the whole previous bucket finished. | the full previous bucket that per-member leaderboard deltas use |
| **Participant** | An active, non-bot member whose value for the metric is above 0 in the period: the population the leaderboard ranks. In the Team benchmark the giving metrics (given, active days, maxed days) share one population, the givers, and received has the receivers. | every member |
| **Team distribution** | The Team benchmark's median, middle half (p25–p75) and most, over the participants other than you, drawn as a **range strip**. Fewer than 2 teammates: none (a median of one is their number); 2–4: the median only; from 5: the rest and your percentile (share strictly below you). Never names anybody. | a leaderboard |
| **Active day** / **Maxed day** | A day with `given > 0` / a day on which the member used their whole allowance (`memberDays.maxed`). | — |
| **Longest streak** | The longest run of consecutive active days inside the period, clipped to it. | the all-time streak on the member row |
| **Reach** | Distinct teammates you gave kudos to in the period. | *received* |
| **Channels** | Distinct channel ids you gave in (ids, because names change). | channel names |
| **Quests completed** | Your Quest completions whose `completedAt` falls on a day of the period (workspace timezone), so a quest week straddling a month, quarter or year edge splits by day. Only ever your own: Past you shows it; Teammate and Team lock it (`personal`, Quest spec D10). Absent while quests are off. | a teammate's or the team's quest count (never shown) |
| **New discoveries** | Bot messages whose first sighting (`discoveries.firstSeenAt`) falls in the period. | the whole collection |
| **Received-derived metric** | A metric that reveals kudos somebody received: *received* and *new discoveries*. Follows `receivedVisibility`; your own discoveries stay yours to see. | giving metrics, which are always visible |
| **Locked row** | A scoreboard row whose values the viewer may not see. The server sends `value: null` and the reason (`hidden`: the workspace hides received counts; `private`: each member sees only their own; `personal`: quests, which are never shown for anyone but yourself); the row is shown with a lock, never dropped. | a metric that isn't offered in a mode, which is simply absent |

## Kudos attempts

Specified in [Slack: bot reactions confirm every kudos attempt](https://github.com/Silthus/kudos/issues/50). Recording lives in `convex/attempts.ts`; reactions and the guidance copy in `convex/lib/guidance.ts`.

| Term | Meaning | Not to be confused with |
|---|---|---|
| **Attempt** | A Slack message (or playground message) that carries the kudos emoji. Recorded once per message (`kudosAttempts`, keyed by workspace + channel + message ts) with who tried and how it ended. Messages without the emoji are never attempts. | *reaction-based giving*, which reacts to someone else's message and has no attempt |
| **Outcome** | How an attempt ended: `given` (every mentioned person got the full amount), `limit` (it would have exceeded the giver's remaining allowance: nothing was given) or `invalid` (nobody valid was mentioned: no mention, only group mentions like @here, only yourself, only bots/the app, only deactivated or unknown people, incl. other workspaces' guests). Giving stays all-or-nothing per message. | — |
| **Bot reaction** | The reaction the Kudos bot puts on the attempt's message: the kudos emoji for `given` (✅ `white_check_mark` if Slack rejects a custom emoji), ⏳ `hourglass_flowing_sand` for `limit`, ❌ `x` for `invalid`. Recorded on the attempt only once Slack shows it. | a member's kudos-emoji reaction, which gives kudos |
| **Guidance** | The ephemeral note to the giver on a failed attempt: how a valid kudos works, with the multiplication (`2 people × 2 🌮 = 4 🌮`) for `limit` and a one-line example for `invalid`. Not rarity-rolled; it rides along with the rolled "limit reached" / "self kudos" reply when there is one. | a rarity-rolled *bot message* |

## Game

Specified in [the game spec](https://github.com/Silthus/kudos/issues/55#issuecomment-5812632101) (settled in [Grill the gamification mechanics with the human](https://github.com/Silthus/kudos/issues/55)). The game is an optional layer on top of kudos whose one purpose is to make appreciating others a daily habit. It only rewards *thoughtful* giving: the Quests' **Qualifying kudos** rule (`hasNote` + no thank-back, `lib/quests.ts`) is the one definition of "counts". The XP rules, the level curve, titles and the game areas are pure in `convex/lib/xp.ts`; the switch, players, the ledger and its rebuild live in `convex/game.ts`, called from the engine's give and revoke.

| Term | Meaning | Not to be confused with |
|---|---|---|
| **Game** | The optional layer of XP, levels, Hog coins, the skill tree, gardens, sprees and boosters. A workspace switches it on; a member becomes a player by giving their first kudos. | the kudos engine, which works with or without it |
| **Game switch** | The admin setting `gameEnabled` (off for new workspaces, on in the demo); also the kill switch. Switching it on plays the kudos history so far through the rules (a rebuild). Switching it off opens a **game pause**: kudos given until it's back on never earn anything, not even in a rebuild. | the Quests switch, which is separate |
| **Player** | A member who has given at least one kudos while the game is on (a `players` row). Before that they can receive kudos, but nothing accrues. A player stays a player. | *joining*, which is only for sprees |
| **Hiding the game** | A member setting that removes the game from their view while kudos keep working. XP keeps accruing, so coming back never costs anything. | leaving the workspace |
| **XP** | Progress points that set your level. Earned by giving and by receiving thoughtful kudos, and by quests. Never spent, never lost except when the kudos behind it is revoked. | Hog coins, which are spent |
| **XP event** | One row of the game ledger (`gameEvents`), written in the same transaction as the kudos that earned it: a `give` event per batch for the giver, with one **line** per recipient row, and a `receive` event per row that earned its receiver XP. A revoke takes back exactly the lines of the rows it removes; later kudos keep what they earned. Each line also carries the **Hog coins** its row earned; receive events never carry coins. | the kudos rows themselves |
| **Demo launch** | The demo's simulated game launch (`lib/demoGame.ts`): the Monday 18 weeks before the current week. The history before it is a **game pause**, so the rebuild of the demo year pays nothing for it and the demo user lands around level 9 on any day of the year; the success baseline is pinned to the three months before it, and the seed window reaches back far enough to hold them. After the rebuild the demo seeds what the rules can't derive: the demo user's skills and garden (`demo.seedGarden`), then the Store story. | the Game switch in a real workspace |
| **Rebuild** (game) | Playing a member's surviving kudos history through the XP rules and replacing their events (`internal.game.rebuildWorkspace`): the backfill when the game is switched on, the demo year, and the repair tool. Without revokes it writes exactly what the live path wrote; after revokes it re-scores later kudos against the history that survived (so a thank-back whose earlier kudos was revoked can then earn XP and coins), and it scores the Unsung bonus by today's received-visibility setting. It replaces `players.coins` too, but never touches coins spent or adjusted. One member per transaction, so a member too big to rebuild can't stop the others. | the read-model rollups' rebuild |
| **Level** | A rank derived from total XP (30, 75, 175, 350, then 50 × L more per level, up to 25), with a **title** (Seedling, Sprout, Gardener, Grove keeper, Elder hog). A level reached is kept even if a revoke takes the XP back. Shown on your profile, never ranked against others. | a leaderboard *rank* |
| **Earnings reply** | The giver's reply to a kudos, ephemeral where they gave it (in the thread, if any; no longer a DM), itemising what it earned while the game is on: "+25 XP · +2 Hog coins · new connection +10 · a real why +5" (coins only once the wallet is open at level 3), or how a kudos without a reason could earn more. | the receiver's DM |
| **Gain** | Something a member discovered or gained, told in a DM (§G13): a new Rare-or-better message discovered where only they saw it (their reply, "limit reached", `/kudos me`; Commons and Uncommons stay marked new in the reply, or the first weeks would be a stream), a level-up with its skill point, a skill or an item gained, a spree tier their kudos reached, a plant reaching a new stage. Every kind and how it reads is in `convex/lib/gains.ts`; a system emits one with `Gains.add` during an event, or `sendGains` outside one (a skill picked on the web). | XP or coins earned, which never get a DM of their own |
| **Gain DM** | The one DM that carries everything an event gained a member (`convex/gains.ts`): if the event already DMs them (the receiver's kudos DM, a quest-complete DM) the gains ride along in it, otherwise it's a DM of its own. Two level-ups in one event read as one. Only for players (a member's first kudos starts the game), never while the game is off or hidden, never a reminder; coins in it only once the wallet is open. Gains never ride in a DM the workspace keeps quiet, and a reply that fell back to a DM already is the discovery. | a stream of DMs, one per gain |
| **Level-up DM** | The gain for reaching a level: its title and the skill point it grants, and from level 3 the Hog coins. Never for members who hide the game. | a DM per XP earned (never sent) |
| **Your game** (Slack) | The member's level, XP to the next one, Hog coins from level 3, and what opens next, on App Home and in `/kudos level` (the same blocks, `convex/lib/gameBlocks.ts`). The garden summary and today's daily quest join it with their tickets. Only for players who see the game. | the web Me page's level panel |
| **Locked area** | A game area the member hasn't reached yet, shown visible but locked with the level it opens at and one line on how to get there (`Locked`, `GAME_AREAS`). Only the next level's areas are shown. | a hidden feature |
| **Hog coin** | The only currency, shown as a gold coin with Max the hedgehog. A thoughtful kudos earns the giver 1 per kudos given (not cut by XP decay or the daily XP cap; the allowance caps it); every level reached earns 10; garden fruit earns up to 14 a week; a weekly quest 5 and the daily quest 2 (from level 5); sprees will earn more. Spent in the Store. Never turns into kudos or allowance, and kudos never turn into coins. | kudos, which are only a stat |
| **Coin balance** | What a member can spend: coins from their game events (`players.coins`, of which garden fruit paid `players.fruitCoins` and quests `players.questCoins`, each shown as its own source) + 10 per level reached − coins spent + admin adjustments (`members.coinsSpent`, `members.coinsAdjusted`), computed by `coinBalance` in `convex/lib/coins.ts`. A revoke takes back the coins its kudos earned and can take the balance below zero, which blocks spending until it's positive again (`canSpend`). Level-up coins stay with the level, even when receiving XP helped reach it (the coins are for the level, not for receiving). Removing a member revokes every kudos they gave or received, so the coins their teammates earned by thanking them go too. | the old received-kudos Store balance (`balanceOf`, ADR 0001) |
| **Wallet** | Where a member sees their Hog coins, from level 3 (Me, `/kudos coins`, and the earnings reply). Coins collect silently before that; the wallet appears with everything collected so far, and the level-3 DM says how much. Below level 3 not even the amount leaves the server. | the Store |
| **Skill tree** | Four branches (Gardener, Herald, Scout, Neighbour) of permanent abilities a member picks with skill points, defined as data in `convex/lib/skills.ts` (`SKILL_TREE`, worth 38 points). There are never enough points to take every skill (24 at level 25), so each member's tree is a choice. Tier 1 is open from the start; tier 2 opens at level 5, tier 3 at 10 and the **capstones** (3 points) at 20. A skill needs its **parent**. Every skill is an ability or a nudge toward breadth, never an XP-from-volume multiplier. Taken skills are `players.skills`; every change is also a `skillChanges` row, so a game rebuild replays skills as they stood at each kudos. | *perks* that come automatically with a level (not used) |
| **Skill point** | Earned one per level-up (so level − 1 in total, and never lost) and spent on one **rank** of a skill; most skills have one rank, some two or three. | XP |
| **Skill reset** | Returns every skill point for Hog coins, spent in the same transaction (`members.coinsSpent`): 50, 100, 200, 400, then 200 more each time (`resetCost`). Needs the wallet (level 3) and the price the member was shown. Also the Store's reset item (`resetSkills`). | uprooting a plant |
| **Arrives with** | A skill whose system hasn't shipped yet (`arrives` on the skill): shown in the tree but can't be taken until its ticket makes it work. | a *locked* tier, which only waits for a level |
| **Lookout** | The Scout skill that gives a member a private list of teammates they've thanked before but not in 30 days or more (**Wide net** adds a few they've never thanked). Only ever the member's own giving. | the Unsung bonus, which is about who *anybody* thanked |
| **Garden** | A member's own garden of plants, each grown for one teammate they recognise (`plants`, `convex/gardens.ts`; pure rules in `convex/lib/garden.ts`). It opens at level 3 with one **plot**; the Gardener skills add plots up to 6. Others see the plants but not whom they're for; there are no garden rankings. | the team garden |
| **Plant** | Grown in your garden for one teammate: **planting** costs 10 Hog coins and needs a qualifying kudos to them in the last 7 days. One growing plant per teammate. It grows through stages (Seed, Sprout, Sapling, Young, Grown, Blossoming, Ancient) by **waterings** and a minimum age, both needed, so it can't be rushed. Only the teammate sees that it's for them ("Ana is growing a Helpful oak for you"), and a DM tells them. | a *reward* |
| **Dormant** | A plant not watered for 60 days: autumn-coloured, no fruit, and its age stops counting (each gap between waterings adds at most 60 days). The next watering wakes it. Plants never die, and dormancy never sends a DM. | deleted |
| **Watering** | The first qualifying kudos from a plant's owner to its teammate in a quest week after the planting week. Never stored: waterings follow from the surviving kudos rows, so a revoke takes its watering back (the plant can un-grow) and a replay can't disagree. Thank-backs, kudos without a reason and kudos during a game pause never water; neither do boosters or bonus days. | a kudos, which may water at most one plant per week |
| **Fruit** | What a Grown or older plant watered in the last 14 days grows, one a day, worth 1 or 2 Hog coins (seeded by plant and day). A plant holds 3 (Good harvest: 4) and then stops growing more; nothing rots. **Picking** it (a click on the garden) pays at most 14 Hog coins and 21 XP (3 per fruit) a quest week, as a `harvest` game event; fruit over the cap waits. Fruit already picked stays picked, even if a revoke later un-grows the plant, and a game rebuild keeps it. | coins from kudos, which a revoke takes back |
| **Memory** | A plant no longer growing: uprooted by its owner (freeing its plot), or grown for a teammate who left. It keeps the stage it had. A plant for a deactivated teammate is a memory only while they're away. | a deleted plant |
| **Team garden** | The workspace's shared garden. It grows from how many different people give thoughtful kudos, never from who receives. Its milestones can trigger bonus days. | a member's garden |
| **Daily quest** | One small thoughtful-giving goal per day, on top of the weekly quest board, only while the game is on and from level 5: *A thoughtful thanks*, *Tell the story* (12+ words), *Widen the circle* (someone not thanked in 30 days, or ever), *Two teammates* (`DAILY_QUESTS`). The same for the whole workspace on a workspace day: a seeded order per workspace that brings each once every four days and never the same two days running (`dailyQuestKey`), nothing stored. Only Qualifying kudos given that day count. Met at most once a day (`dailyQuestCompletions`), paid 10 XP + 2 Hog coins, shown in the earnings reply, no DM and no Quest message; a revoke that un-meets it takes it and its pay back. Missing it costs nothing. | the weekly *quest board* |
| **Quests on the ladder** | With the game on, the quest board and the daily quest open at level 5 (`QUESTS_LEVEL`); below it both are listed *locked* and nothing progresses. From level 5 each weekly quest pays 20 XP + 5 Hog coins and a clean sweep 30 XP more, once a week (`QUEST_REWARDS`), as `quest` XP events tied to their completion (`completionId`; the sweep to the completion it was paid on, `sweepPaid`), written in the completion's transaction and found by `batchId` (`quest:<completion>`, `sweep:<member>:<week>`). Only a revoke takes pay back: exactly what the completions it removes were paid (a sweep moves to the completion now holding the flag if that one was paid, else goes back). A board that reopens because a teammate joined keeps its pay, and a revoke never pays. Quest messages stay. With the game off, quests work as before under their own switch and pay nothing; with quests off there are no quests at all. A member who hides the game doesn't see quests (they still play and pay silently, and Quest messages are collected without a DM). Your level is public and reflects quest effort indirectly; *which* quests you completed stays private (changes Quest spec D7, D8, D10). A **rebuild** pays the stored completions whose moment the replayed history had reached level 5 by, including completions from before the game was switched on; completions made below level 5 or during a game pause stay unpaid. Quests are the one area shown locked from level 1 on (§G11 "visible but locked before"), not only from the level before, since the board and daily quest are already part of every quest surface. | quests paying allowance or kudos (never) |
| **Booster** | A consumable, bought with Hog coins, that makes recognition better for a while or for someone else. Some are company-wide and announced with who activated them. | a skill, which is permanent |
| **Bonus day** | A day on which thoughtful kudos earn extra, announced in advance. Triggered by a team-garden milestone, an admin, or a company-wide booster. | a *streak* (the game has none) |
| **Super kudos** | A special kudos emoji a member can use a limited number of times a month once they've taken its skill. It gives the usual amount; the receiver gets a unique celebration. | giving more kudos |
| **Kudos spree** | What a thoughtful kudos becomes when enough teammates join it: 5, then 10, 20, 50 and 100 people (the **tiers**). Each tier reached pays the waiting joins out to the receiver and is celebrated in the kudos' thread. | reaction-giving |
| **Join** (a spree) | Choosing to add your kudos to someone else's thoughtful kudos, by clicking the bot's reaction and confirming. It reserves one of today's kudos per person named and uses one of your monthly **spree joins** (5 a month by default). The kudos only reaches the receiver when the next tier is reached; if it isn't, the spree join comes back. | *becoming a player* |
| **Reaction-giving** | An admin setting: reacting with the kudos emoji to a plain message gives its author a bare kudos. Separate from sprees. | joining a spree |
| **Game item** | Something in the Store that applies instantly and needs no approval: a cosmetic, a booster, extra spree joins, a skill-tree reset. Defined in `ITEMS` (`lib/items.ts`: name, price, monthly limit) with its effect in `ITEM_EFFECTS` (`convex/items.ts`); a new item never touches the Store core. An extra spree join (8 coins, 5 a month) adds a join to the month it's bought in; the skill-tree reset is the skill tree's own reset (`resetSkills`/`clearSkillTree`, #92) at its price (`resetCost`: 50, 100, 200, 400, then +200), counting resets made on the skill tree page too. | a *reward*, which an admin fulfils |
| **Success metrics** | How admins judge whether the game works, per workspace month: *reach* (distinct recipients per active giver, should rise), *says why* (share of kudos with a 12+ word Note, should rise), *thank-backs* (share of Reciprocal kudos, must not rise) and participation. A kudos counts once per person recognised, whatever its amount. Admins only, on Analytics, with a CSV export; kept in the `successStats` rollup. | the Analytics KPIs, which follow the selected period |
| **Baseline** | The success metrics pooled over the three calendar months before the game's launch month (`workspaces.successBaselineBefore`, pinned by `anchorSuccessBaseline` when an admin first switches the game on), or before the current month until the game launches. Quiet months count, months before anyone ever gave don't. Only whole months after the baseline are judged against it. The workspace switch is the kill switch if the metrics move the wrong way. | a *benchmark* in Compare |
| **Presence** | Who is in the shared world right now and where (#155, `convex/presence.ts`, rules in `lib/presence.ts`): a `worldPresence` row per member and sign-in session (every demo visitor is the same member, each their own hog), written by the client's **heartbeat** (at most 4 a second walking, every 20 s standing) and read by 32×32-tile **chunk** (`nearby`, at most 9 chunks, 50 hogs each) and as the **online list** (`online`, at most 200 names). A hog seen in the last minute is online; older rows are never shown and the cron sweeps them after ten. Only within the workspace and only while the game is shown to both: hiding the game leaves the world at once; a workspace with the game off, or the shared demo mid-reset, has nobody in it. Where you stand is saved to `players.at` (at most every 10 s standing, every minute walking), so you reappear there; someone who never walked appears at the base camp. Never who is offline. | the *online* status in Slack |
| **Look** (hog) | How a member's hog looks to everyone in the world: one of Hedgehog Mode's colour filters and one of its accessories, or none (`players.look`, set in the cabin with `setLook`; the option lists are copied into `lib/presence.ts`). Needs a player. | the *cosmetics* a member wears on their profile (`members.look`: frame, banner, sticker) |

## Demo, playground and simulator

| Term | Meaning | Not to be confused with |
|---|---|---|
| **Shared demo** | The seeded demo workspace "Lumen Labs" (`T_DEMO_LUMEN`) that "Explore the live demo" signs into. Every visitor is the same demo user (Alex Rivera), so everything done in it is shared, and a nightly reset (`demo.startDemoReset`) seeds a fresh year. | a visitor's **simulator** |
| **Playground** | The demo's pretend Slack channel (`demo.simulateMessage` and friends): a message runs the exact pipeline of a real Slack event, in whichever demo workspace the visitor is in (the shared demo or their simulator). | a separate engine |
| **Workspace clock** | A workspace's "now": the wall clock plus its `clockOffsetMs` (`workspaceNow`, `convex/lib/time.ts`). Every write path reads the time through it, so the day a kudos lands on, the allowance, quest weeks and daily quests, plant ages, spree windows and bonus days all follow the workspace's own days. Only simulators have an offset; every real workspace and the shared demo are on the wall clock. The web client adds the offset to compute the workspace's today (`useWorkspaceToday`, from `session.viewer`'s `clockOffsetMs`). System timestamps (sign-in recency, rollup markers, locks, Slack signatures, a simulator's start and expiry) stay on the wall clock. | the workspace *timezone*, which only says where its days start |
| **Simulator** | A demo visitor's private workspace (`convex/simulator.ts`, `workspaces.simulator`): the demo's settings and emoji, the visitor (Alex, admin) and 12 teammates without any history, the game, quests and sprees on, and its own **workspace clock** starting at the next morning. It belongs to the visitor's sign-in session, not to the shared demo user (its visitor member has no `userId`), so no other visitor ever sees it; one per session, and starting again resets it. It shows in the workspace switcher as "Simulator" next to the shared demo. A demo workspace (`isDemo`) without a Slack install: it never posts to Slack. Stopping it, starting again and the hourly cron (7 days after it started) wipe it in steps of at most 1,500 rows (`demo.wipeActivity`). | the shared demo, which it never touches |
| **Join at a level** | Starting a simulator at level 1–25: the visitor gets that level's XP floor as one **seed event** (a `seed` XP event, `seed:<member>`), so its skill points and level-up coins follow as usual; no kudos, no garden, no discoveries. A seed event is never a kudos: it counts in no kudos stat, success metric or earnings reply, and a game **rebuild** keeps it like fruit and spree pay. | XP earned by giving |
| **Advance** | Moving a simulator's clock to 09:00 local on a day 1–30 days later (calendar days, so a DST switch never skips a day) and running what those days would have: the allowance is back, sprees whose window ran out lapse, plants that grew say so, a new quest week and today's daily quest open, a bonus day starts. Returns what changed. | waiting for the wall clock |
| **Fast-forward** | A bot playing the visitor up 1–24 levels through the real engine, one scheduled mutation per simulated day (a `simulatorRuns` row the client subscribes to; abortable between days): detailed-note kudos to rotating teammates up to the allowance (its plants' teammates first, their weekly watering), fruit picked, a plant in a free plot when the coins allow; never skills, those are the visitor's. Ends with a summary (days played, kudos, thoughtful kudos, quests, coins, fruit, plants, levels, new connections) and the days each level took. | the demo seeding, which bypasses the engine |
