# Website

The browser package, the signed-in surface where a member sees their kudos beside App Home: a React shell in the PostHog brand, light and dark, with the HedgeHug logo beside the wordmark in its header, above the name on the sign-in and closed pages and as its favicon, built by Vite and served from the deployment's own `*.convex.site` root by the static hosting component, after Slack's routes, with a strict Content Security Policy header on every HTML response. The shell holds no member data: it signs in with Slack through Convex Auth's React client and returns to the page the sign-in started from, keeping the one-time code in the query string until Convex Auth redeems it, renders one page from the one answer getMyProfile gives (closed, signed-out, verifying, unverified, not-a-member or member), where a member's home leads with a character header: the member's face as a portrait, while the answer carries a progression a neutral level ring filled to the level's share and named for the level and the XP to the next, then the member's name as the page title, the invitation to thank someone and its one action in Slack before every counter, while there is a progression a full-width neutral XP bar, the kudos left today as the header's one big number with a pip for each kudos of the base and the refill time, the lifetime given and received in one quiet line, and Max's line on this week; then the profile card that keeps received kudos private and shows the level when there is one, the same filled ring on the avatar menu while there is a level, and the later features: while the answer carries no unlock path, as plain locked cards, with the leaderboard as a plain card linking to its page while the answer says it is open; while it carries one, only the shipped features it lists, in three groups in its order, "Ready for you" as closed crates labelled with what each unlocks and an outline "Open", "Open" linking to the feature's page or pointing there with an action to Slack, and "Still locked" with "Unlocks at level {level}" and no progress. While the answer carries Journey steps, a Journey panel sits between the hero and those groups, listing each active step's goal, hint and XP, a finished step as its reward crate with an outline "Open", and an opened one as done, with no step count. The path picks the page: the home at `/`, the leaderboard at `/leaderboard` with its period in the query string, the quests at `/quests`, the Book at `/book`, the skill tree at `/skills`, and the not-found page everywhere else. The screen nav links `/` and each open feature that has a page, and its page renders the one answer getLeaderboard gives for the period: the board card with the member's standing, a headline naming the lead, a neutral podium where a tie stands level, the rest of the window with a gap line, the whole board centred on the member with their row pinned and "Jump to me" while it is scrolled away, the private improvement line and how it counts, or one hedgehog and an action to Slack when nobody is ranked; while the answer is locked, Max says that sentence instead, with a link home, and while it is ready, the page shows the crate with a primary "Open" in its place. The quests page renders the one answer getQuests gives the same way: this week's quest cards with their kind, goal, a neutral progressbar, the XP and a "Swapped" tag, a finished quest as its reward crate with an "Open", primary for the first crate on the page, and an opened one as done, the crates of earlier weeks waiting to open, each with the week it is from in the browser's language and an "Open", one hedgehog and an action to Slack when nothing was drawn, and how quests work, with no swap, group or bonus quest. The Book page renders the one answer getBook gives the same way: under the title "Achievements", one plain card per ladder in the answer's order, with the ladder's hedgehog emblem in silhouette until a tier is earned, a neutral progressbar to the next tier, and its four tiers, each a neutral metal medal with one to four pips and its word, the date it was earned in the member's time zone, or the count it needs, the next one tagged "Next"; it shows no total, no closest next tier and no reward. The skill tree page renders the one answer getSkillTree gives the same way: the skill points to spend, one band per shipped row with each perk a button that names its state and cost and says so in a visible label while chosen, the chosen perk's details beside the tree on wide screens and in a drawer on narrow ones, with its copy word for word, its level, its cost and then when it was bought, why it can't be bought yet, or a primary button that sends buyPerk and resends the same request after an unreachable server, with what was bought, a refusal or an unreachable server said in a live region, the perk chosen again for every answer, a refusal or an unreachable server said visibly in the page's live region while a narrow screen's details are closed, a refusal without a reason or an unreachable server kept beside the perk until the read shows it owned, and focus on the perk's details once it is bought, the perks owned in purchase order, and how perks work; while the profile carries skill points, the HUD shows their count as a link to `/skills`. A crate's "Open", and the HUD's ready pill, which counts the ready features, then the Journey's, this week's and earlier weeks' quest crates, and takes the first, send openFeature or openQuestCrate with the crate's own quest from the read and say "Opening…" until it answers: only "opened" plays the full-screen reveal, once per member and crate in this browser by the read's opaque seen key, skipped by a click or a key, shown at once under reduced motion, with a button to play it again and one to close it, a quest crate's labelled "Quest reward" or "Journey reward" with "You earned {xp} XP" and a link to this week's quests while Quests is open and the reveal didn't start on /quests, and focus back on the feature's card, the quest's card, the Journey step or the page title; a refusal or an unreachable server is said in a live region, which also says what opened. It shows "Sign-in didn't finish" when a sign-in this browser started comes back signed out or Convex Auth's redemption of the one-time code Slack's return brings is rejected, which Convex Auth drops unhandled and would otherwise leave loading forever, shows "Can't reach HedgeHug" when the socket to the deployment stays unconnected for five seconds while the answer is still loading, sets the theme from a blocking script in the page's head before the first paint, signs out from the avatar menu, and moves focus to the page title when the answer changes; a fixture build renders the same pages from typed fixtures.

## entrances
- route GET /*: a browser asks for a page or a built asset of the website; a path without a file falls back to the shell
  handler: registerWebsite in convex/website/hosting.ts
  trust: browser
  control: none — it serves public static bytes built from this repository, which hold no member data and no secret; every HTML response carries the Content Security Policy header that forbids framing and foreign scripts (WS25)
